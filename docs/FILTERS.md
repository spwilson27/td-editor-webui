# Filters library (v6 phase A)

Generated by `.venv/bin/python scripts/effects_dev.py report --results DIR` from live runs (TouchDesigner GLSL TOP chain in `/project1/_fxdev` vs the
WebGL2 runner in headless Chromium).  Sources: `shared/effects/<type>.filter.json` (spec: parameters, units, passes, extent, samples) +
`<type>.glsl`; planners `td/raster_editor/effects.py` == `web/src/engine/effects/{filters,plan}.ts` (checked by `shared/effects/vectors.json` and the seeded
`fuzz_vectors.json`); types `shared/effects/filters*.d.ts`.

## Using filters

- **Per-layer effect:** put the filter in `effects` (same chain as the v5 effects, mixed lists fine).
- **Adjustment layer:** run the filter on the document-sized composite BELOW the layer: web `applyEffects(compositeBelow, [filter], rect, out)`, TD
  `EffectChain.apply([filter], below_top, w, h)`.  Nothing else is special.
- **Second image (displace by layer / input):** web `applyEffects(src, fx, rect, out, auxSurface)`; TD `EffectChain.apply(fx, input, w, h, aux=top)`.
  Aux is document sized; absent aux = no displacement.
- **Planner flags** (per effect, identical in Python / TS): `effect_reads` / `effectReads` (`none|point|neighbourhood|global`),
  `effect_needs_neighbourhood`, `effect_td_preview` / `effectTdPreview`, extent / reach for region rendering (`expandRect`).
- Everything is static (no time); iterative filters take `iterations` <= 64 and deterministic seeds.

### Whole-document (global-extent) filters

These read pixels anywhere in the document (or depending on parameters), so an edit anywhere re-renders the whole document region; the planner reports
`reads: global` and an extent of 2^20 px for them (`expandRect` clips to the document).  Avoid stacking them on huge layers while painting: `crt`, `kaleidoscope`, `lensDistortion`, `polar`, `radialBlur`, `ripple`, `tileMirror`, `twirl`, `zoomBlur`.
(`displace` only with edge != transparent, `feedback` / `echo` only with rotate / scale or large offsets, `crt` only with curvature.)

## Blur pyramid

Blur sizes (kernel half width, sigma = size / 3) up to 16 px run as one exact separable gaussian (bit-identical to v5).  Above (cap 200 px) every blur-type pass (shadow,
glows, bevel, blur, unsharp, high-pass, bloom) runs as a pyramid: box down-sample by s = 2^L (smallest L with ceil(size / s) <= 16, L = 1..4), gaussian at low resolution with
sigma_low^2 = (sigma^2 - s^2/4) / s^2, bilinear up-sample; the block grid is aligned to document coordinates (partial == full renders) and has one margin texel per side.
Cost is ~constant in the size.  Measured vs an exact gaussian (`web/tests/browser/effects.filters.test.ts`, 256x192, 8-bit): radius 12..16 max 0.96/255; 17: 1.53; 24: 1.13; 32: 1.11;
33: 2.06; 48: 1.15; 64: 1.10; 65: 2.03; 100: 1.62; 130: 2.43; 200: 1.22 (mean 0.19-0.35/255 throughout).  Continuity at the threshold for the v5 effects (16 -> 17 px vs the natural
15 -> 16 step): dropShadow 7.0 vs 7.0, outerGlow 9 vs 8, innerGlow 14 vs 13, bevel 14 vs 14 (max /255).

### Exactness notes

- `dither` (error diffusion, ordered), `kuwahara` quadrant choice, `posterize` and the `edgeDetect` threshold take their decisions in **integer arithmetic on the 8-bit straight colour**
  (exact unpremultiply `min((510 k + m) / (2 m), 255)`).  This makes them identical across GPUs **only for 8-bit inputs**: when the chain feeds them float16 intermediates (after another
  effect with rgba16float output) the recovered integers can differ by one level and the decision can flip.  Dither diffusion is a windowed (7 rows x 19 columns) Floyd-Steinberg, an
  approximation of the sequential algorithm.  `unsharp`'s threshold is a +-1 level ramp for the same reason.
- Coordinate-mapping filters use `fxSin / fxCos / fxAtan2` (polynomials, only + - * / sqrt) instead of the GPU trig, which differs by far more than 1e-3 px on software rasterisers.
